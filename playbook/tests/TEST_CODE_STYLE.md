# test_code_style.py

> **Add tests here when:** changing `tools/check_code_style.py` (a rule, an exemption, the baseline or the command line), or the "Code style" rule of `INVARIANTS.md` that it checks.

- **Kind:** pure Python. Snippets of code are fed to `check_source()` as text, so no file is written for a rule; the command line is run against a temporary repo (`REPO_ROOT` and `BASELINE_PATH` are replaced).
- **Needs:** nothing.
- **Covers:** each rule has a snippet that breaks it and one that follows it: a blank line before `elif`/`else`/`except`/`finally`; type hints on every parameter and return (`self` and `cls` excepted); a module docstring; a period ending a comment block or a trailing comment (a directive, a URL, a shebang and a `# ---- divider ----` excepted); a period ending each prose paragraph of a docstring (a lead-in ending in a colon and a command or indented example excepted); snake_case names (an Enum member, a module constant and a CapWords object such as `SessionLocal` excepted); spelled-out names (a one-letter name, `df`, and the words of `ABBREVIATIONS`); a name bound from `pd.read_csv()` and its kin ending in `_df` (not `sheet_name=None`, which returns a dict); module constants above the first function (unless one needs a function, like a list of checks); no more than `MAX_STATEMENTS_WITHOUT_BLANK_LINE` statements in a row (imports, constants, field declarations and asserts never count, and a comment line ends the run). `tests/` skips type hints, short names, constant order and the wall rule. A file that cannot be parsed is reported as `syntax`. The baseline forgives only what it lists, by file, rule and line text and never by line number, and the command line fails on a new violation and on a stale baseline entry. Virtual environments, `node_modules` and the playbook are not scanned, even when a file in one is named by hand; `--update-baseline` refuses named files. The whole repo stays inside `tools/code_style_baseline.json`, and the checker and its own test pass without any baseline.
- **Not here:** `black -S` (blank lines after a signature, line wrapping, quotes), which the CI gate runs by itself; the JavaScript rules (ESLint and Prettier).
- **Known gaps:** a rule that needs judgment is not checked: that a name is abbreviated outside the `ABBREVIATIONS` list, that a docstring is needed when a name already says it, that an inline comment says why and not what, that a blank line sits between *steps* rather than just somewhere. The wall rule counts statements, so a block of 6 long ones passes.
